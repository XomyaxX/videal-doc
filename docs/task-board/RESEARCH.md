# Доска задач: что уже есть на GitHub

Дата сверки: 10 ноября 2026. Цифры звёзд и даты пушей взяты из GitHub API в этот день, не из памяти. Смотрели чужие публичные репозитории, не репозитории студии.

Задача студии: одна страница внутри Videal.Doc (Next.js 16, React 19, Prisma, SQLite), карточки с исполнителем, статусы «к выполнению / в работе / готово», связи «блокирует / зависит от / дальше по порядку», запрет циклов, нормальная анимация. Продукт закрытый и коммерческий, поэтому лицензия должна позволять такое использование. Предпочтительны MIT, Apache-2.0 и BSD. AGPL и GPL для встраивания в закрытый код не подходят. Отдельный сервер «рядом» владелец не просил: доска должна жить в этом приложении и в его базе.

## Что не берём целиком

Focalboard, Planka, Kanboard, Vikunja и OpenProject — готовые трекеры со своим входом, своей базой и своим меню. Встроить их в страницу Videal.Doc значит тащить второй сервер либо копировать чужой интерфейс. У трёх из них лицензия (AGPL, GPL или Fair Use) не подходит закрытому коммерческому продукту. Kanboard по MIT можно было бы поставить рядом, но это PHP и отдельный продукт, а студии нужна страница внутри CRM на уже существующих сотрудниках.

tldraw по качеству холста лучший, но лицензия прямо запрещает боевое использование без ключа. Для закрытого теста в офисе это всё равно прод.

Excalidraw — MIT и живой, но это доска для рисунков. Исполнители, статусы и запрет циклов пришлось бы писать самим поверх очень большого редактора.

## Рекомендация

Встроить библиотеку **[@xyflow/react](https://github.com/xyflow/xyflow)** (MIT) и не копировать чужой трекер.

Почему именно так:

- Лицензия MIT. Её можно использовать в закрытом коммерческом CRM, сохраняя текст лицензии в зависимостях npm.
- Репозиторий живой: пуш 9 ноября 2026, десятки тысяч звёзд, типы на TypeScript.
- Рёбра — штатная возможность: порты на карточке, стрелка, подпись, анимация штриха, пан и зум. Циклы библиотека не проверяет, это правило нашей модели, и его лучше держать в своём коде и в базе.
- Стек совпадает: React 19 и клиентский компонент Next.js. Отдельный сервис не нужен. Сотрудники остаются в таблице `User`.
- Карточки полностью свои, поэтому легко сделать тёмный клетчатый фон, жёлтый заголовок и зелёное описание, как просил владелец.
- Колонки по статусу и по человеку не требуют второй тяжёлой библиотеки. В проекте уже есть такой приём на `/prod/board` (обычный HTML5 drag). dnd-kit можно добавить позже, если колонок станет много и нативный drag начнёт мешать.

frappe-gantt оставляем кандидатом на фазу с датами: лицензия MIT, но последний заметный пуш был в июне 2026, и это не карточки.

Свою модель данных при этом не заимствуем из Kanboard и OpenProject дословно. Берём только смысл: ребро всегда означает «сначала одно, потом другое», тип связи — подпись (блокирует, зависит, следующий шаг), цикл запрещён до записи.
